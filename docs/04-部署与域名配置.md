# 04 · 部署与域名配置（1Panel）——已拍板方案

> 目标形态：`chunk.rubyc.cn` → 1Panel 网站反向代理 → Next.js Docker 容器 → **1Panel 自带 PostgreSQL** / **应用商店 MinIO**
> 🔴 拍板结论（2026-10-09）：数据库用 1Panel 自带 PG（不新装）；应用 Docker 化；
> 公网入口 = 1Panel 网站反代 `chunk.rubyc.cn`；MinIO 独立容器（应用商店安装）。

---

## 一、总览

```
公网
 │  A 记录: chunk.rubyc.cn      → 服务器 IP
 │  A 记录: media.chunk.rubyc.cn → 服务器 IP（可选，直连媒资；不建则走 /media 反代）
 ▼
┌──────────────────────────── 服务器（1Panel） ────────────────────────────┐
│                                                                          │
│  1Panel-Nginx (:80/:443)                                                 │
│    ├─ chunk.rubyc.cn        → 127.0.0.1:3000   【网站·反向代理】          │
│    └─ media.chunk.rubyc.cn  → 127.0.0.1:9000   【网站·反向代理·只读】      │
│                                                                          │
│  容器 chunk-english-app    :3000   ← 本项目编排（deploy/docker-compose） │
│  容器 1Panel-postgresql-*  :5432   ← 🔴 1Panel 自带 PG，只建库不装新容器  │
│  容器 1Panel-minio-*       :9000(API) :9001(控制台) ← 应用商店 ★独立容器  │
│                                                                          │
│  网络：三者都挂在 1panel-network，app 用容器名直连 PG/MinIO               │
│  数据卷：1panel_volumes/{postgresql,minio}                               │
└──────────────────────────────────────────────────────────────────────────┘
```

**端口原则**

| 组件 | 监听 | 是否对公网 |
|---|---|---|
| Nginx 80/443 | `0.0.0.0` | ✅ 唯一入口 |
| chunk-english :3000 | `127.0.0.1` | ❌ 只给 Nginx |
| PostgreSQL :5432 | `127.0.0.1` / 内网 | ❌ |
| MinIO API :9000 | `127.0.0.1` / 内网 | ❌（公网走 Nginx 反代） |
| MinIO 控制台 :9001 | `127.0.0.1` | ❌ 需要时用 SSH 隧道访问 |

> ⚠️ **最容易犯的错**：把 9000/9001 直接放公网。MinIO 被扫到就是全桶裸奔。

## 二、部署步骤（按顺序执行）

### 步骤 1 · DNS 解析

在域名服务商（rubyc.cn 所在处）添加：

| 记录类型 | 主机记录 | 记录值 | TTL |
|---|---|---|---|
| A | `chunk` | 服务器公网 IP | 600 |
| A | `media.chunk` | 服务器公网 IP | 600 |

验证：`dig +short chunk.rubyc.cn` 应返回服务器 IP。

> 若暂时不想开 media 子域，跳过第二条，改走 `chunk.rubyc.cn/media/` 反代路径（见步骤 6 备注）。

### 步骤 2 · 数据库（用 1Panel 自带 PG）+ MinIO（应用商店）

**PostgreSQL——🔴 不新装，用 1Panel 自带的**：

1. 确认自带 PG 在跑：`docker ps | grep 1Panel-postgresql`（记下完整容器名，如 `1Panel-postgresql-Htbt`）
2. 1Panel → 数据库 → PostgreSQL → 创建数据库：
   - 库名 `chunk_english`，权限用户 `chunk_user` + 强随机密码
   - 记下 `用户名/密码/库名`（后面填 .env）
3. 无需动端口映射：app 容器与 PG 同在 `1panel-network`，**容器名直连**

**MinIO——1Panel 应用商店安装（独立容器）**：

### 步骤 3 · 配置 MinIO（独立容器）

1. 进 MinIO 控制台（本地 SSH 隧道）：
   ```bash
   ssh -L 9001:127.0.0.1:9001 root@<服务器IP>
   # 浏览器打开 http://127.0.0.1:9001
   ```
2. **Buckets → Create Bucket**，建两个：
   - `chunk-public` —— 建好后进 Bucket → Access Policy → **Custom**，设为匿名 `s3:GetObject`（公开读）
   - `chunk-private` —— 保持 Private（默认）
3. **Access Keys → Create**，生成一对**应用专用**密钥（不要直接用 root 账号的）：
   ```
   Access Key: chunk-app
   Secret Key: <随机生成，存进 1Panel 的 .env>
   ```
4. CORS（前端直传跟读录音需要）：MinIO → Configuration → 加规则
   ```json
   [{"AllowedOrigin":["https://chunk.rubyc.cn"],
     "AllowedMethod":["GET","PUT","HEAD"],
     "AllowedHeader":["*"],"ExposeHeader":["ETag"],"MaxAgeSeconds":3600}]
   ```

### 步骤 4 · 上传代码

```bash
ssh root@<服务器IP>
mkdir -p /opt/apps/chunk-english && cd /opt/apps/chunk-english
# 方式一：Git
git clone <你的仓库地址> .
# 方式二：本地 rsync（首次未建仓库时）
# rsync -avz --exclude node_modules --exclude .next ./ root@<IP>:/opt/apps/chunk-english/
```

### 步骤 5 · 环境变量 + 启动容器

```bash
cd /opt/apps/chunk-english/deploy
cp .env.example .env
vim .env        # 填 DATABASE_URL / MINIO_* / AUTH_SECRET / NEXTAUTH_URL
```

`.env` 关键项（**逐条确认**，错一个就连不上）：

```ini
NODE_ENV=production
APP_PORT=3000
NEXTAUTH_URL=https://chunk.rubyc.cn
AUTH_SECRET=<openssl rand -base64 32>

# PostgreSQL：🔴 1Panel 自带 PG 的真实容器名（docker ps 查看）
DATABASE_URL=postgresql://chunk_user:<pwd>@1Panel-postgresql-Htbt:5432/chunk_english?schema=public

# MinIO：应用商店容器的真实容器名；⚠️ 9000 是 S3 端口，不是控制台 9001
S3_ENDPOINT=http://1Panel-minio-xxxx:9000
S3_REGION=us-east-1
S3_ACCESS_KEY=chunk-app
S3_SECRET_KEY=<步骤3的Secret>
S3_BUCKET_PUBLIC=chunk-public
S3_BUCKET_PRIVATE=chunk-private
S3_PUBLIC_BASE=https://media.chunk.rubyc.cn/chunk-public
SIGN_GET_TTL=900
SIGN_PUT_TTL=600

FREE_EPISODE_LIMIT=5
```

> 🔴 **容器名直连的前提**：`deploy/docker-compose.yml` 已把 app 加入 `1panel-network`
> （1Panel 自带 PG 与应用商店 MinIO 都在这个网络），所以 `.env` 里直接写容器名即可。
> 容器名以 `docker ps` 实际输出为准；若网络名不同，`docker network ls` 确认后改 compose。

用 **1Panel → 容器 → 编排 → 创建编排**，粘贴 `deploy/docker-compose.yml`（见下方文件），
或直接 `docker compose up -d --build`。

### 步骤 6 · 首次初始化（数据库 + 管理员）

```bash
docker compose exec app npx prisma migrate deploy    # 建表
docker compose exec app npm run seed                 # 写入套餐 + 初始管理员
docker compose logs -f app                           # 确认无报错
curl -I http://127.0.0.1:3000                        # 本机应 200
```

`npm run seed` 之后**立刻登录改掉初始管理员密码**（`.env` 里的 `SEED_ADMIN_EMAIL/PASSWORD`）。

### 步骤 7 · 1Panel 建站（反向代理）

**网站 → 创建网站**：

| 字段 | 值 |
|---|---|
| 类型 | 反向代理 |
| 主域名 | `chunk.rubyc.cn` |
| 代理地址 | `http://127.0.0.1:3000` |
| 备注 | 苑说英语官网 |

再建一个给媒资（若做了 media 子域）：

| 字段 | 值 |
|---|---|
| 主域名 | `media.chunk.rubyc.cn` |
| 代理地址 | `http://127.0.0.1:9000` |

> **没建 media 子域时**：在 `chunk.rubyc.cn` 的 Nginx 配置里加
> `location /media/ { proxy_pass http://127.0.0.1:9000/; }`，
> 并把 `S3_PUBLIC_BASE` 改成 `https://chunk.rubyc.cn/media/chunk-public`。

### 步骤 8 · 申请 SSL 并强制 HTTPS

1. **网站 → chunk.rubyc.cn → HTTPS → 申请证书**，选 Let's Encrypt，勾选域名（含 `www` 如需）。
2. 开启 **强制 HTTPS**（HTTP 301 → HTTPS）。
3. `media.chunk.rubyc.cn` 同样申请。
4. 开启 **HSTS**（确认全站 HTTPS 无混合内容后再开）。
5. 证书自动续期：1Panel 默认开启，检查「计划任务」里有证书续期任务。

### 步骤 9 · 备份（1Panel 计划任务）

| 任务 | 类型 | 频率 | 命令 / 目标 |
|---|---|---|---|
| 数据库备份 | 脚本 | 每日 03:00 | `docker exec <pg容器> pg_dump -U chunk_user chunk_english \| gzip > /backup/chunk-$(date +\%F).sql.gz` |
| MinIO 备份 | 目录备份 | 每周日 04:00 | 备份 MinIO 数据卷目录到对象存储/异地 |
| 备份留存 | — | — | 保留 14 天 |

## 三、发布与更新流程

```bash
cd /opt/apps/chunk-english
git pull
cd deploy && docker compose up -d --build app    # 只重建 app
docker compose exec app npx prisma migrate deploy   # 有迁移才需要
```

**回滚**：镜像打 tag（`chunk-english:$(git rev-parse --short HEAD)`），回滚时把 compose 里的 `image` 改回上一 tag 重启。

**上线前自检清单**

- [ ] `chunk.rubyc.cn` HTTPS 打开首页，无 mixed content 警告
- [ ] 未登录访问第 6 集 → 换词表音频被锁
- [ ] 注册 → 邮箱验证 → 登录 → 兑换码 → 变成会员 → 第 6 集解锁
- [ ] 20 个词逐个点发音都有声（说明 MinIO Key 全对）
- [ ] 跟读录音能上传、能回放（私有桶预签名通了）
- [ ] `curl -I https://chunk.rubyc.cn/api/episodes` 返回 200
- [ ] 9000/9001 从公网**不可访问**（`nc -zv <IP> 9001` 应超时）

## 四、常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 容器起不来，报 `P1001 can't reach database` | compose 与 PG 不在同一 Docker 网络 | 把 PG 容器名加入 compose 的 `networks`，或用 1Panel 应用名 `1Panel-postgresql-xxxx` |
| 音频 403 | bucket 未设公开读 / Key 拼错（大小写） | 控制台看 `chunk-public` 策略；Key 必须与 `lib/media.ts` 一致 |
| 音频 404 | `ep_slug` 用了 `CK001` 而实际存的是 `ck001` | 统一小写 |
| 预签名 URL 用了 `http://minio:9000` | 内部地址浏览器不可达 | 签发时把 host 换成公网 `S3_PUBLIC_BASE`（本项目在 `lib/minio.ts` 里做替换） |
| 上传大文件失败 | Nginx `client_max_body_size` 默认 1M | 网站配置加 `client_max_body_size 200m;` |
| 会员权限不生效 | 只改了前端 / 有缓存 | 权限判定在 SSR + API 双侧；`memberships.expires_at` 用 UTC 比较 |
| Let's Encrypt 申请失败 | DNS 未生效 / 80 端口被占 | `dig` 确认解析；检查 1Panel 是否占用了 80 |
