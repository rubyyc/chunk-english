# 01 · 技术方案

> 结论先行：**Next.js 15 全栈单体 + PostgreSQL + MinIO（独立容器）**，
> 用 1Panel 编排部署，Nginx 反代 + Let's Encrypt。

---

## 一、架构选型

### 1.1 推荐方案 A：Next.js 全栈单体（默认）

```
                    ┌──────────────────────────────────┐
   chunk.rubyc.cn   │  Nginx (1Panel 网站/反代 + SSL)   │
   ────────────────▶│  :443 → 127.0.0.1:3000            │
                    └───────────────┬──────────────────┘
                                    ▼
                    ┌──────────────────────────────────┐
                    │  chunk-english (Next.js 15)      │
                    │  ├─ App Router 页面（SSR/SSG）   │
                    │  ├─ Route Handlers = REST API    │
                    │  ├─ Auth.js（会员会话）          │
                    │  └─ Prisma ORM                   │
                    └───────┬──────────────────┬───────┘
                            ▼                  ▼
              ┌─────────────────────┐  ┌──────────────────────┐
              │ PostgreSQL 16       │  │ MinIO（独立容器）     │
              │ 业务/用户/会员/进度 │  │ 音视频/封面/卡片/录音 │
              └─────────────────────┘  └──────────────────────┘
```

选它的理由：

| 理由 | 说明 |
|---|---|
| 单容器 | 一个 Node 进程搞定页面 + API，部署面最小，1Panel 编排最简单 |
| SEO / GEO | SSR + 结构化数据，页面能被搜索引擎和 AI 爬虫正读（你要的 GEO） |
| API 不浪费 | Route Handlers 本身就是标准 REST，未来做小程序/App 直接复用，不用重构 |
| 边际成本低 | MinIO 用 S3 兼容 SDK，预签名直传，Node 侧代码极少 |
| 与你现有栈一致 | Next.js（岐黄拾光）+ PostgreSQL + Docker/1Panel 都是你在用的 |

### 1.2 备选方案 B：前后端分离

```
Next.js（SSR 页面 + BFF）  ──HTTP──▶  FastAPI（SQLAlchemy + Alembic）
                                            │
                                     PostgreSQL / MinIO
```

| 维度 | 方案 A（单体） | 方案 B（分离） |
|---|---|---|
| 容器数 | 2（app + 可选 redis） | 3（web + api + 可选 redis） |
| 会员/权限逻辑 | TypeScript 写 | **Python 写（复用 OneAI 经验）** |
| 未来小程序/App | 复用 Route Handlers | **天然是独立 API，最干净** |
| 首版开发速度 | **更快** | 稍慢（要维护两套工程 + CORS + 会话打通） |
| 与现有项目协同 | 独立 | 与 OneAI 同构，模型/中间件可抄 |

**判定**：一人公司场景，首版冲速度 → **选 A**。只有当你确定「半年内必做小程序/App + 想要后端全 Python」时才选 B。

### 1.3 技术栈明细

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Next.js 15（App Router, TypeScript） | React Server Components 减少客户端 JS |
| 样式 | Tailwind CSS v4 + shadcn/ui | 与视频端配色统一（朱红 `#E23C20` + 近黑 + 白） |
| ORM | Prisma | 迁移用 `prisma migrate deploy`，1Panel 部署时执行 |
| 数据库 | PostgreSQL 16 | 1Panel 应用商店一键安装 |
| 认证 | Auth.js (NextAuth v5) | Credentials（邮箱+密码）+ 微信 OAuth（二期） |
| 密码 | argon2id | 不要用 bcrypt 裸哈希 |
| 会话 | JWT（httpOnly Cookie） | 无状态，免 Redis；要强制下线再上 Redis 会话 |
| 对象存储 | MinIO（独立容器） | S3 兼容，`@aws-sdk/client-s3` + `s3-request-presigner` |
| 媒体处理 | ffmpeg（构建期，非运行时） | 视频转码/压缩在本地或 CI 做，**不要放运行时容器** |
| 支付 | 一期兑换码；二期微信支付 Native | 二期再接，先跑通权限 |
| 部署 | Docker Compose + 1Panel 编排 | 见 `docs/04` |
| 备份 | 1Panel 计划任务（pg_dump + MinIO 数据卷） | 每日 03:00 |

## 二、仓库目录结构

```
chunk-english/
├── app/                          # Next.js App Router
│   ├── (marketing)/              # 公开页
│   │   ├── page.tsx              # 首页
│   │   ├── chunk/page.tsx        # 合集列表
│   │   ├── chunk/[no]/page.tsx   # ⭐ 单集学习页
│   │   ├── words/page.tsx        # 词库检索
│   │   └── pricing/page.tsx      # 会员定价
│   ├── (auth)/login|register|reset/page.tsx
│   ├── (member)/me/…             # 个人中心（需登录）
│   ├── admin/…                   # 后台（需 admin 角色）
│   └── api/                      # Route Handlers = REST API
│       ├── auth/[...nextauth]/route.ts
│       ├── episodes/route.ts
│       ├── media/sign/route.ts   # 签发 MinIO 预签名 URL
│       ├── progress/route.ts
│       ├── shadows/route.ts      # 跟读录音
│       ├── orders/route.ts
│       └── admin/…               # 管理端接口
├── components/
│   ├── learn/                    # FrameworkCard / ItemCard / QuizCard / WordTable / ShadowRecorder
│   └── ui/                       # shadcn 基础组件
├── lib/
│   ├── prisma.ts                 # Prisma 单例
│   ├── auth.ts                   # Auth.js 配置
│   ├── permission.ts             # 🔴 权限判定唯一入口
│   ├── minio.ts                  # S3 client + 预签名
│   └── media.ts                  # 对象 Key 拼装（唯一真源）
├── prisma/
│   ├── schema.prisma
│   ├── migrations/
│   └── seed.ts                   # 初始管理员 + 会员套餐
├── scripts/
│   └── sync_episode.py           # 🔴 本地一键同步（内容+封面 → 管理 API，见 docs/07）
│                                 # ⚠️ import_episode.ts 已作废（旧方案产物）
├── public/
├── deploy/
│   ├── docker-compose.yml
│   ├── .env.example
│   └── Dockerfile
├── docs/
└── README.md
```

**关键约定**

- `lib/permission.ts` 是**判断"这个用户能不能看这集"的唯一入口**，页面、API、SSR 全调它，不散落 `if`。
- `lib/media.ts` 是**对象 Key 的唯一拼装处**，任何地方不手写 `audio/ck001/01_en.mp3`。
- 音频/视频**不进 Git**，全在 MinIO；仓库只存代码与数据 JSON。

## 三、里程碑（建议按此顺序，每步可验收）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M0 地基**（0.5 天） | 骨架 + Prisma 连 PG + MinIO 连通 + 1Panel 跑通 Hello | 域名 HTTPS 打开首页无报错 |
| **M1 内容只读**（1.5 天） | 内容同步链路（本地一键同步 + **服务器 TTS 生成音频**，见 [docs/07](07-内容同步与服务器TTS方案.md)）+ 合集列表 + 单集学习页（六段交互） | CK001 六段都能用，20 个词逐个发音 |
| **M2 用户与权限**（2 天） | 注册/登录/找回 + 会员套餐 + 权限拦截 + 免费 5 集边界 | 未登录/免费用户/会员三种视角行为正确 |
| **M3 学习闭环**（1.5 天） | 进度、收藏、生词本、跟读录音留存 | 刷新后进度还在 |
| **M4 后台与变现**（1.5 天） | 管理端（内容/用户/订单/看板）+ 兑换码 | 后台发码 → 用户兑换 → 权限生效 |
| **M5 SEO/GEO**（0.5 天） | sitemap、JSON-LD、OG、llms.txt、每集静态页 | 每集有独立可索引 URL |

> 合计约 **7.5 人日**（不含内容量扩张）。M0–M2 做完就能对外见人。

## 四、性能与容量预期（先给量级，避免过早优化）

| 指标 | 预估 | 对策 |
|---|---|---|
| 单集音频体积 | 约 **1.5–2 MB**（24 段：框架 + 例句 + 20 词；服务器 edge-tts 产出 mp3） | MinIO 直出，Nginx 侧开 gzip/brotli 无意义（已压缩），依赖 CDN 可选 |
| 成片 | 🔴 **不上站**（用户已拍板） | 无；成片只用于抖音/视频号/B站三端发布 |
| 1000 集时素材量 | 音频 ≈ 1.7 GB + 封面 ≈ 1 GB（**无视频**） | MinIO 单盘够用；超过 50 GB 再考虑挂载独立数据盘 |
| 并发 | 冷启动期 < 100 并发 | 单 Node 容器足够；先不引入 Redis，有需要再加 |

## 五、已知风险

| 风险 | 影响 | 对策 |
|---|---|---|
| ~~视频带宽成本~~ | 已消除：网站**不放视频**（成片只上抖音/视频号/B站） | 无需防盗链；封面图体积可忽略 |
| **服务器 TTS 连通性** | 境内服务器连 edge-tts 依赖的 `speech.platform.bing.com` 不稳 → 音频生成失败 | 上线前 10 次连通性实测；不稳走 TUN 代理出站；终极兜底本地生成上传（详见 [docs/07 §10](07-内容同步与服务器TTS方案.md)） |
| MinIO 端口暴露公网 | 极危险 | MinIO S3 API **只监听内网**，公网只经 Nginx 反代只读路径；管理台 9001 不对外 |
| 会员内容被白嫖 | 音频 URL 泄漏 | 会员音频走**预签名短时效 URL**（5–15 分钟），不存永久直链 |
| 权限判定散落 | 漏判会送内容 | 强制单入口 `lib/permission.ts`，Code Review 检查 |
